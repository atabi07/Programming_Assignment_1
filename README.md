# EC551 — Verilog Logic Synthesis Engine, v4

Fall 2026 PA1. Version 4 adds **PNG/JPG circuit photograph input** with an
interactive picture-overlay gate/wire annotation editor and an optional
**AI-suggested draft** (external vision API, key required). The saved annotated
photo becomes a verified circuit graph that feeds the existing SystemVerilog
minimizer, testbench, reports, and Nexys A7 wrapper. This is NOT claimed to
be a reliable fully-automatic local computer-vision parser for arbitrary
handwriting.

## What runs where?

- `src/logic_engine_tb.sv` is a **SystemVerilog program running on your PC via Icarus Verilog**. It parses SOP cubes, computes truth tables, performs exact minimum-literal SOP/POS optimization, and generates structural Verilog. **It is not synthesizable.**
- `scripts/run.py` (Python standard library only) is the Windows-friendly CLI, checks input files, translates symbols/graphs/schematics into canonical SOP truth tables, launches SystemVerilog analysis and simulation, and saves reports. **Minimization and netlist generation remain in SystemVerilog.**
- `scripts/symbolic_inputs.py` implements a recursive-descent Boolean expression parser and standardized gate-label aliases.
- `scripts/logisim_input.py` imports basic saved Logisim `.circ` XML: components, port coordinates, and wire connections.
- `scripts/photo_editor.py` lets you load your photo, annotate gates/wires over it, confirm and save the circuit.
- `scripts/photo_input.py` strictly validates photo provenance/annotation and saves a review image.
- `scripts/photo_vision.py` optionally suggests initial gate and wire annotations using an online vision API; results must be reviewed.
- `output/<case>/verilog/minimized_logic.v` is the **synthesizable structural Verilog** generated by the engine. `nexys_top.v` attaches A–D to switches SW0–SW3 and Y to LED0.
- `tests/tb_generated.sv` **simulates** every possible input combination and records the result. An Icarus simulation **never programs a connected FPGA**.
- Only Vivado synthesis, implementation, bitstream creation, and Hardware Manager programming can put the circuit on the Nexys A7-100T.

## Requirements

Windows 10/11 or Linux/macOS, Python **3.10+**, `iverilog` and `vvp` available on `PATH`. For photo inputs, install Pillow (`python -m pip install pillow`); Tkinter is typically bundled with Windows Python. For physical hardware, AMD Vivado and Nexys A7-100T are also required.

Check installation in **PowerShell**:

```powershell
python --version
iverilog -V
vvp -V
```
### Installing Icarus Verilog on Windows (via MSYS2)
1. Install MSYS2 from msys2.org (default folder C:\msys64).
2. In the MSYS2 terminal: `pacman -S mingw-w64-ucrt-x86_64-iverilog`
3. In Git Bash, add it to PATH:
   `echo 'export PATH="/c/msys64/ucrt64/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc`
4. Check: `iverilog -V` and `vvp -V`

## Quick start on Windows (PowerShell)

Open PowerShell in the **project root** (the folder containing `scripts`, `src`, `examples`), then:

```powershell
# See all 12 command options
python scripts/run.py --list-commands

# All 12 operations on SOP input + exhaustive netlist simulation
python scripts/run.py --input examples/majority.sop

# Execute only command 5 (minimized SOP and literal savings)
python scripts/run.py --input examples/majority.sop --command 5

# Execute only command 7 (prime implicant count)
python scripts/run.py --input examples/majority.sop --command 7

# Process a graph-based gate circuit instead of an SOP file
python scripts/run.py --input examples/majority.graph.json --command all

# Mathematical symbols in a Boolean expression
python scripts/run.py --input examples/majority.symbols.expr

# IEC labels as gate types in a graph file
python scripts/run.py --input examples/majority.iec.graph.json

# Read a saved Logisim schematic (actual gates and wires)
python scripts/run.py --input examples/asymmetric.logisim.circ

# A sample circuit PNG with accompanying human-verified annotations
python scripts/run.py --input examples/asymmetric_photo.png

# Open YOUR own phone photo to trace/confirm symbols and wires
python scripts/photo_editor.py "C:/Users/you/Pictures/my_circuit.jpg"
# After clicking Save in the editor (produces my_circuit.graph.json):
python scripts/run.py --input "C:/Users/you/Pictures/my_circuit.jpg"

# Run the complete regression suite (including actual Icarus simulations)
python scripts/test_all.py
```

All commands also accept `--output-dir C:/some/folder`. Use `--no-simulate` to skip the generated-netlist test. Output folder names are based on input filenames (for example `majority_sop` and `majority_graph_json`). Running the same case **overwrites that case's previous reports**; use a different `--output-dir` to preserve earlier results.

For example, `python scripts/run.py --input examples/majority.graph.json` creates:

```text
output/majority_graph_json/
    summary.json                   Source, truth vector, paths, simulation status
    reports/analysis.txt           Engine's chosen commands / metrics
    reports/simulation.txt         All input combinations, actual vs. expected
    reports/simulation.csv         Machine-readable input, actual, expected, PASS/FAIL

    waves/simulation.vcd           Waveform; open in GTKWave
    verilog/minimized_logic.v      Structural gates (synthesizable)
    verilog/nexys_top.v            Nexys A7 switch/LED mapping

    work/engine.vvp                Compiled analysis engine
    work/nettest.vvp               Compiled generated-netlist simulation
```

A `PASS: all 8 generated-netlist combinations` means the **generated Verilog was verified against all 8 Boolean input combinations in simulation**. `$finish called at ...` only means the simulation ended. Neither output proves hardware programming.

## Architecture / data flow

    input file (.sop / .json / .expr / .circ / photo)
            |
    scripts/run.py  -- validates input; non-SOP inputs are evaluated to a
            |          truth table and written as canonical SOP minterms
            v
    src/logic_engine_tb.sv (Icarus)  -- parses SOP -> truth table,
            |          minimizes ON-set (SOP) and OFF-set (POS),
            |          prints commands 1-12, self-checks SOP = POS = truth,
            |          writes minimized_logic.v + nexys_top.v
            v
    tests/tb_generated.sv (Icarus)  -- simulates the generated netlist on
            |          every input vs. a truth vector computed in Python
            v
    Vivado  -- minimized_logic.v + wrapper + XDC -> bitstream -> Nexys A7

## NEW: Photo-to-circuit input (PNG, JPG, JPEG, WEBP, BMP)

This genuinely **loads a picture**, but there is a critical engineering boundary:
pixels alone do not guarantee correct electrical topology. The offline workflow
is therefore **photo-guided annotation**, not automatic recognition. It works
with a picture taken on your phone and does not require the original schematic
source file. Optionally you can request AI-assisted initial recognition, but
it is unverified until you review it.

1. Transfer the photo from your phone to Windows. Take it square-on with good
   contrast, all wires visible, and clearly label 2–4 inputs as A, B, (C, D)
   plus an output Y. Use only combinational gates for this prototype.
2. In PowerShell, run:

   ```powershell
   python -m pip install pillow
   python scripts/photo_editor.py "C:/Users/you/Pictures/logic.jpg"
   ```
3. The image appears in a window. Select `A` and click the corresponding label
   in the photo. Do the same for B (and C/D if present). Select `AND`, `NOT`,
   etc. and click each gate center. For `CONNECT`, click a **source** node and
   then a **destination gate**. Repeat for every wire. `SET OUTPUT` and click
   the gate or input driving Y. Undo, Move and Delete are supported.
4. Select **Check circuit** to validate connections and see the Boolean truth
   table. **Check the blue connectivity arrows against actual drawn wires and
   verify polarity bubbles**; a topologically valid graph may still represent
   an incorrectly traced circuit. Click **Save verified graph** (confirmation
   required) to create `logic.graph.json` next to the photo.
5. Click **Save & Run engine** or run manually:

   ```powershell
   python scripts/run.py --input "C:/Users/you/Pictures/logic.jpg" --command all
   ```

   This rechecks that the photo has not changed (SHA-256), evaluates the graph,
   generates structural Verilog, and saves `output/logic_jpg/reports/photo_trace.png`,
   `analysis.txt`, `simulation.csv`, and `waves/simulation.vcd`.

### Optional automatic first pass (online vision API)

This is **experimental**; not tested with arbitrary photographs and it may
misinterpret crossing wires, small inversion bubbles, blurred labels, or
unfamiliar drawing conventions. It costs API credits and transmits the image
to OpenAI. It is not required for offline use.

In PowerShell, set your own API key in the *current session* (do not put a key
in code or commit it to Git):

```powershell
$env:OPENAI_API_KEY = 'paste-your-own-api-key-here'
python scripts/photo_editor.py "C:/Users/you/Pictures/logic.jpg"
```

Then click **AI Suggest (optional online)**, approve upload, and review/edit
every gate, label, connection, and bubble. **AI proposals are never silently
accepted or immediately programmed onto the FPGA.** A user must confirm Save.
The API request uses the Responses endpoint with base64 image input and
structured JSON; model availability and pricing depend on your account.

**Limitations:** No fully automatic, reliable offline recognition of arbitrary
handwriting; one output; 2–4 inputs; supported combinational gates are
AND/OR/NOT/NAND/NOR/XOR/XNOR/BUF. The graph describes logic connectivity,
not wire-routing geometry. A review overlay draws logical links between
annotation markers, which may differ from the physical paths of the pen strokes.
These limitations are deliberate: misread circuitry should never pass through
as a purportedly verified netlist.

## Supported inputs

### 1. SOP cube files (`.sop`)

The first whitespace-separated token is input count 2, 3 or 4. Following tokens are AND terms containing exactly N symbols, where `1` is a positive literal, `0` is a complemented literal, and `-` means don't-care. All terms are OR-ed. Variable order is **A, B, C, D** (A is the most significant bit).

Example `majority.sop`:

```text
3
11-
1-1
-11
```

This is `F = AB + AC + BC`. All-zero functions contain **no terms** after the input count; all-one functions contain one all-`-` term. Output don't-care minterms are not supported.

### 2. Gate graph JSON files (`.json`)

`examples/majority.graph.json`:

```json
{
  "inputs": ["A", "B", "C"],
  "gates": [
    {"id": "ab", "type": "AND", "inputs": ["A", "B"]},
    {"id": "ac", "type": "AND", "inputs": ["A", "C"]},
    {"id": "bc", "type": "AND", "inputs": ["B", "C"]},
    {"id": "out", "type": "OR", "inputs": ["ab", "ac", "bc"]}
  ],
  "output": "out"
}
```

- Gates: `AND`, `OR`, `NOT`, `NAND`, `NOR`, `XOR`, `XNOR`, `BUF`, `CONST0`, `CONST1`, `EXACTLY1`, with case-insensitive word names and symbol aliases described below.
- Single-output, acyclic combinational circuits. Fanout, shared gates, and gates defined out of order are supported.
- `NOT` and `BUF` have one input; `CONST0/CONST1` have zero; the other gates have two or more.
- The parser rejects missing nodes, duplicate IDs, cycles, incorrect fan-in, and unknown gate types.
- The Python front-end evaluates **all** input combinations, emits equivalent canonical SOP minterms, then calls the **existing SV optimizer**. The generated netlist may have a different gate topology but must be functionally equivalent.
- The current engine limits either input type to 2–4 inputs and **one output**; a large graph with thousands of nodes is not a scalable general-purpose mapper.

### 3. Mathematical Boolean expressions (`.expr`)

Use `∧` AND, `∨` OR, `¬` NOT, `⊕` XOR, `↑` NAND, `↓` NOR,
`⊙` XNOR. ASCII `&`, `|`, `!`, `~`, `^`, `*`, `+` and words
`AND`, `OR`, `NOT`, etc. also work. Parentheses, postfix complement
`A'`, and implicit AND (`AB`, `(A+B)C`) are accepted. Priority:
NOT > AND/NAND > XOR/XNOR > OR/NOR. Mixed NAND/NOR chains should
use explicit parentheses because they are not associative.

`examples/majority.symbols.expr`:

```text
INPUTS: 3
Y = (A ∧ B) ∨ (A ∧ C) ∨ (B ∧ C)
```

Or write `F = AB + AC + BC`. Inputs are A..D, with the number
inferred from the highest variable unless `INPUTS: 2/3/4` is given.
An optional `F=` or `Y=` starts the equation.

### 4. IEC, ANSI/IEEE and Unicode gate symbols in graph files

Gate types can be expressed in `type` or `symbol` (same semantics; if both
are present, they must agree). The following equivalents are supported:

| Function | Supported gate identifiers |
|---|---|
| AND | `AND`, `&`, `∧`, `·`, `*` |
| OR | `OR`, `≥1`, `>=1`, `∨`, `+`, `|` |
| NOT | `NOT`, `¬`, `!`, `~` |
| XOR (odd parity) | `XOR`, `⊕`, `^` |
| Exactly-one (IEC) | `EXACTLY1`, `=1` |
| NAND | `NAND`, `⊼`, `↑` |
| NOR | `NOR`, `⊽`, `↓` |
| XNOR | `XNOR`, `⊙`, `≡` |
| Buffer | `BUF`, `BUFFER`, `1` |

**Important:** For three or more inputs, the IEC `=1` means *exactly one*
input high (so `111` produces 0), whereas parity XOR produces 1 for
`111`. Treating these as synonyms would introduce a logic bug. A small
circle (inversion bubble) on a gate's **output** is represented by
`"output_bubble": true` and on selected **inputs** by
`"negated_inputs": [0,2]` (zero-based indices).

```json
{
  "inputs": ["A", "B"],
  "gates": [
    {"id": "g1", "symbol": "&", "inputs": ["A", "B"],
     "output_bubble": true}
  ],
  "output": "g1"
}
```

This represents NAND, including the IEC `&` and the small output circle.
The graph's wires are still represented by the `inputs` connections.

### 5. Saved graphical schematics — experimental Logisim `.circ`

Logisim-evolution supports ANSI/IEEE gate shapes and IEC rectangle symbols,
and saves gates and their wire geometry in an XML `.circ` project. The
importer reads the **saved schematic's semantic component definitions and
wire connections**, *not* shapes in a screenshot. It converts the circuit
to the same graph structure as a JSON input. The parsed circuit is available
at `output/<case>/work/parsed_graph.json`.

Supported subset: a single main circuit, 2–4 labeled one-bit input pins
`A..D`, one one-bit output pin labeled `Y` (or `F`, `OUT`), straight wires,
fanout, ordinary 1-bit AND/OR/NAND/NOR/XOR/XNOR/NOT gates (2–8 gate inputs)
and basic input-pin inversion. Gate orientations and common widths are
interpreted using Logisim's pin-coordinate rules. Unsupported subcircuits,
sequential components, buses, gates with tri-state outputs, unconnected pins
or multi-driver nets produce errors instead of unreliable results.

Example:

```powershell
python scripts/run.py --input examples/asymmetric.logisim.circ
```

**Not supported:** general JPG/PNG screenshots, arbitrary PDFs, unstructured
SVG vector art, or hand-drawn circuit recognition. Those require a separate
computer-vision/wire-reconstruction pipeline, and should be verified visually.

## Individually selectable commands

Supply `--command 1` through `--command 12`, or `--command all` (default):

| Number | Analysis |
|---|---|
| 1 | Canonical SOP |
| 2 | Canonical POS |
| 3 | Inverse canonical SOP |
| 4 | Inverse canonical POS |
| 5 | Minimum-literal SOP + literal savings |
| 6 | Minimum-literal POS + literal savings |
| 7 | Prime implicant count |
| 8 | Essential prime implicant count |
| 9 | ON-set minterm count |
| 10 | OFF-set maxterm count |
| 11 | Custom: truth table |
| 12 | Custom: SOP/POS equivalence test |

Selecting one command **only restricts displayed analysis**; the engine still computes both optimized forms for internal consistency checking and generates the minimized circuit so it can be tested. The output files are saved to the same organized folder.

## Testing

`python scripts/test_all.py` performs the input/parser unit tests (including symbols, native schematic wiring, graph-vs-SOP agreement, cycle rejection, and IEC exactly-one semantics), then—with Icarus installed—runs exhaustive gate-level simulations for SOP, graph, symbol, and schematic examples, including constants and an **asymmetric circuit** `F = A B'`. The asymmetric test catches the A=SW0 and A=most-significant-truth-bit mapping issue that symmetric majority might hide.

The separate testbench verifies `LED0` against the expected truth vector passed to `+EXPECTED=`; expected values are calculated in Python from the original SOP cubes or gate graph, **independently of the SV optimizer's minimized output**. A waveform file `.vcd` can be opened in GTKWave. A CSV contains every tested input combination.

You can also manually run the testbench against existing outputs:

```powershell
iverilog -g2012 -s tb_generated -o nettest.vvp output/majority_sop/verilog/minimized_logic.v output/majority_sop/verilog/nexys_top.v tests/tb_generated.sv
vvp nettest.vvp +VARS=3 +EXPECTED=e8 +CSV=output/majority_sop/reports/manual.csv +WAVE=output/majority_sop/waves/manual.vcd
```

## FPGA: NOT deployed automatically

**Connecting the Nexys A7 to USB does not cause Icarus to run on it.** The code in `output/.../verilog/` is ready to bring into Vivado. Do not add `src/logic_engine_tb.sv`, `tests/tb_generated.sv`, or Python to the synthesis project.

Manual Vivado procedure:

1. Create an RTL project for Nexys A7-100T (part `xc7a100tcsg324-1`).
2. Add `output/majority_sop/verilog/minimized_logic.v` and `nexys_top.v` as **design sources**.
3. Add `constraints/nexys_a7_100t.xdc` as a **constraints file**.
4. Set synthesis top to `nexys_top`.
5. Run **Synthesis → Implementation → Generate Bitstream**.
6. In **Hardware Manager**, choose **Open Target → Auto Connect → Program Device**, select the generated `.bit` file and program the FPGA.
7. Set `SW0=A`, `SW1=B`, `SW2=C`; for majority, LED0 is on when at least two switches are on.

Optional Vivado batch build (generates a `.bit` without programming hardware):

```powershell
vivado -mode batch -source scripts/build_bitstream.tcl -tclargs output/majority_sop
```

Tested on a Nexys A7-100T in Vivado: majority.sop (3 inputs) and big4.sop
(4 inputs) were synthesized, programmed, and verified on all switch combinations.

Pin locations in `constraints/nexys_a7_100t.xdc` correspond to Digilent's [Nexys A7-100T Master XDC](https://github.com/Digilent/digilent-xdc/blob/master/Nexys-A7-100T-Master.xdc).

## Known limitations and AI attribution

- Exact exhaustive prime-implicant subset enumeration scales poorly; limited to 2–4 inputs. More scalable methods (e.g. Espresso or Quine–McCluskey with scalable covering) would be needed for many variables.
- One Boolean output only; no truth-table don't-cares, sequential gates, clocked behavior, or timing/power optimization. Logisim importer supports only the stated subset.
- Individual commands are **CLI-selectable**, not a live interactive GUI.
- Parser unit tests were run in the preparation environment. Icarus HDL compilation/simulation and Vivado FPGA deployment **must be run locally** (no simulators/hardware were available to the assistant).
- **Generative AI use:** Architecture and source code developed with ChatGPT (OpenAI), October 2026. EC551 requires citing AI assistance and being able to explain and defend the algorithms and architecture during the demo.
